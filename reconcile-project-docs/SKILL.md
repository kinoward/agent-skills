# 项目文档整理

让项目文档准确描述当前状态，并保留能指导后续工作的经验。依据当前会话、项目文件和可核实的验证结果，完成文档更新、合并、清理与引用修复；不把会话复述变成另一套项目记录。

## 适用范围

- 默认使用当前会话，包括已提供的上下文摘要，以及当前项目的代码、配置、文档和相关差异。不扫描其他 Codex 任务、全局会话目录或归档；跨会话回顾属于独立任务，可在明确要求时使用 `distill-session-history` 等可用能力。
- 用户指定目录、文件、主题或仅要求审查时，遵守该范围；局部修订不升级为全仓库整顿。普通编码结束、询问项目状态、写文章或提交代码，不自动触发本流程。
- 文档维护可直接完成范围内的更新、合并和有依据的清理。默认不修改业务代码、恢复服务、提交 Git、升级版本或改变项目权限；发现实现缺口时如实记录，不顺带修复。
- 沿用目标项目的文档语言、结构、术语和工作规则。无需为了使用本技能创建固定的 `docs/`、ADR、知识库、待办体系或文档报告。

## 工作流程

### 1. 建立范围和基线

阅读适用的 `AGENTS.md`、文档导航与维护规则，定位当前会话涉及的文档及其引用者。Git 项目先查看工作树状态和已有差异；没有 Git 时依实际文件核对，不把 Git 当作前置条件。保留与任务无关的现有改动。

识别手写说明、生成文档、历史记录与活动计划。生成文件按项目约定修改文档真相源、运行生成命令；不要直接修补下次会被覆盖的产物。若需要改变业务代码或生成器实现才能解决，单独报告该缺口。

### 2. 核实事实并提炼经验

从当前会话提取最终需求、后续修正、撤回方案、已完成行为、未解决问题，以及值得保留的原因或执行经验。针对受影响路径核查代码、配置与有效验证证据，不为了凑结论遍历无关模块。

按信息用途判断证据：

| 信息 | 判断方式 |
| --- | --- |
| 需求与预期规范 | 依据当前用户意图和项目已确认规则；代码暂未满足规范不等于规范应该降低 |
| 已实现行为 | 依据当前代码、配置及对应行为证据；会话中的计划、旧回复和“已完成”字样只是线索 |
| 验证与现场状态 | 区分检查已运行、代码已构建、服务已恢复和实际业务已验证；历史结果保留当时范围，不推断为本次通过 |
| 经验 | 保留有证据、可复用且会改变后续决策或执行的经验；一次性报错、猜测和已放弃方案不升格为通用规则 |

会话缺失或事实冲突无法消解时，标注未确认范围，继续处理可确认内容，不补采其他任务。规范与实现冲突时分别描述实际状态、预期要求及缺口，不通过改文档宣称问题已修复。

### 3. 分配事实归属

在工作上下文中为候选结论确定证据、目标文档和处理方式：新增、修正、合并、删除、已覆盖或待确认。该清单用于决策，不默认保存为新文件。

产品用法、架构、数据或权限边界、执行流程、验证要求和未完成事项，分别落到项目已有的对应文档。易变事实尽量由一个来源维护，其他位置引用。已覆盖的经验保留原落点，在交付中指出即可，不重复扩写。

经验总结应给出适用条件、原因、可执行的检查或做法，以及完成证据；按复杂度写到足够使用即可。不要把本项目的端口、目录、命令、技术栈或测试规模泛化为其他项目的要求。

### 4. 更新、收敛与清理

修正错误和过时描述，统一同一事实的术语、完成状态和适用范围。只有结构调整确实改善查找或消除重复时才移动章节或文件，不为统一外观重写整个文档体系。

删除段落、文件或完成计划前，逐项检查：

- 内容是否已经失效，或已被当前权威文档和相关验证完整吸收。
- 是否仍有独有的决策背景、恢复依据、风险、测量条件或未完成事项；有价值内容先迁入合适的现有落点，必要历史记录明确日期和适用范围。
- 引用者、导航、生成索引和锚点是否需要同步修复。

不以年代、篇幅或位于 completed 目录为唯一删除理由；不把遗留问题随过程记录一起删除。没有足够依据时保留并说明疑点。

已有文档已经准确时可以不修改。重复执行不新增例行会话报告、不重复写入经验，也不只为显示“已整理”而刷新日期、改标题或搬动内容。

不把原始对话、凭据、访问链接、进程号、截图或临时命令输出写入长期文档；必要的历史证据只保留与结论相关的范围和出处。临时笔记用完清理，不建立 processed-state、分析进度或会话已处理标记。

### 5. 验证与交付

先检查本次差异、删除后的引用和前后语义一致性，再执行目标项目明确要求的文档、生成或其他检查。没有强制要求时采用最小充分验证，不因本技能固定运行完整构建或测试套件。

只有涉及对应文件时才采用已有的导航或待办维护技能；不自动安装依赖、创建缺失的维护体系，或对目标项目运行本技能的自校验工具。

简要交代：

- 更新、合并或删除了什么，以及重要的保留理由。
- 接受或已经覆盖的经验分别位于哪里。
- 仍未解决、待确认或证据不足的事项。
- 实际执行的检查及其结果；不把未运行项或旧结果表述为本次通过。

“文档准确”“流程已记录”和“运行问题已恢复”是不同结论，分别以实际证据报告。
