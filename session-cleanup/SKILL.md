# 会话收尾清理

目标：防止临时文件堆积占满存储，同时让本会话的成果完整落地。用户准备关闭会话时，收好本会话的尾，把剩下的临时产物移入废纸篓，报告释放了多少空间，并明确告诉用户现在能否安全关闭。

## 底线

- **会话记录永不删除。** 各 harness 的会话、历史、记忆与配置（`~/.claude`、`~/.codex`、`~/.gemini`、`~/.cursor`、`~/.hermes`、`~/.agents`、`~/.orca`、Orca 用户数据目录、任何 `*.jsonl`、`sessions/`、`transcripts/` 等）都是宝贵数据，不清理、不移动、不改写。脚本已内置这份保护清单，并拒绝处理其中路径。
- 只处理本会话创建或导致产生的文件；会话开始前已存在的文件、其他会话或用户自己的改动一律不动。
- 依赖目录、虚拟环境、构建缓存不在范围内，除非用户明确要求。
- 用户发起收尾，即授权本流程内的动作：完成遗留、修正文档漂移、清理临时文件、本地提交。会话中只针对某一轮的临时限制（"这轮先别提交""先别清理"）不再阻止收尾；用户明确作为长期要求的限制（"这个项目不要提交"）继续遵守。用户主动推迟的任务不算遗留，只报告。
- 不推送、不开 PR。收尾不授予本流程以外的权限；破坏性、远程、公开或明显扩大范围的动作先问用户。

## 辅助脚本

`scripts/sweep.py`（本技能目录下，仅标准库，`python3 -I` 运行）负责扫描、计量和移动，用紧凑输出代替逐条手工命令：

```bash
python3 -I <skill-dir>/scripts/sweep.py scan [路径...] [--since 3h] [--keep 'GLOB']
python3 -I <skill-dir>/scripts/sweep.py trash 路径... [--keep 'GLOB']
```

- `scan`：Git 仓库列出未跟踪项（整目录折叠，带占用空间和创建时间）与已跟踪修改；非 Git 目录必须给 `--since`，列出此后新建的项。标记：`U` 未跟踪、`N` 新建、`M` 已跟踪修改（只报告）、`P` 受保护（永不处理）。
- `trash`：逐个路径校验后移入废纸篓（无 `trash` 命令时移到 `~/.agents-session-trash/<时间>/`），拒绝受保护、被 Git 跟踪、仓库根目录和家目录，并汇总这些项占用的磁盘空间。
- `--keep` 追加保护规则，可重复。

## 流程

### 1. 重建本会话足迹

依据会话上下文列出本会话写过的文件、建过的目录（含 harness 的 scratch 目录、Orca `chat-scratch`、`/tmp` 下本会话建的目录）、启动且仍在运行的进程或服务，以及承诺过的结果。对涉及的仓库和目录运行 `scan` 交叉核对；`--since` 取会话开始时间，拿不准就往前放宽。脚本只给候选，归属以会话证据为准；无法确定归属的项归入"待确认"。

### 2. 完成未做完的事

逐项核对承诺过的结果。范围内、已获授权、能在当前会话完成的遗留直接做完并做最小充分验证；需要新授权、明显扩大范围或无法完成的，记入报告，不硬做。

### 3. 修正本会话造成的文档漂移

只修本会话改动直接导致过时的路径、命令、状态或流程说明，遵循项目文档约定；不扩大成全面文档整理。

### 4. 建立保护清单并分类

保护清单由三部分组成，命中即保留：

1. **内置**：脚本内置的会话记录、harness 状态与密钥规则（`P` 项）。
2. **项目约定**：项目 `AGENTS.md`、README 等声明的产物目录、数据文件、固定输出；用 `--keep` 传给脚本。
3. **本会话认定**：用户要的交付物，被保留文件引用的文件（import、链接、配置），符合项目结构、准备入库的测试和文档。

其余候选按用途分类，不以文件名或扩展名为准：

| 类别 | 典型内容 | 处理 |
| --- | --- | --- |
| 保留 | 命中保护清单 | 不动 |
| 临时 | 一次性脚本、调试或探索用测试、预览 HTML、截图、日志、导出数据、上述产物的中间输出 | 移入废纸篓 |
| 待确认 | 归属或用途拿不准；临时位置里看起来有价值的内容 | 不动，列给用户 |

"用户要求生成"不等于"要保留"：为展示、验证或一次性查看而生成的可视化、预览页、截图、临时报告默认是临时，只有用户要求保存、放在项目约定位置或被保留文件引用时才保留。

### 5. 清理

把"临时"项一次性交给 `trash`，逐个列出路径，不用通配符，不用 `rm`。本会话创建、清理后变空的目录一并处理。停止本会话启动、已无用途的进程或服务，用户要求保留的除外。

### 6. 提交本会话的改动

清理之后再提交，避免临时文件混入。只暂存本会话负责且应入库的明确路径，不 `git add -A`，不碰不属于本会话的改动。遵循项目的提交规则；环境里有提交类技能（如 `git-commit`）时按其执行。项目规则或用户要求不提交时跳过，并在报告中列出未提交项。不推送。

### 7. 复查

再次运行 `scan`：确认没有遗留的本会话临时项、没有误伤保留项，未提交改动都有交代。对交付结果重跑最小的验证。仍无法安全处理的项写明原因。

## 交付

先给结论，只列有内容的部分：

- **结论**：`可以关闭`，或 `暂不关闭` 并说明原因（有未完成事项、未提交的有价值改动、待确认文件等）。
- **释放空间**：`trash` 汇总的大小与去向；移入废纸篓的空间在清空废纸篓后才真正释放，如实说明。
- **已完成与提交**：补完的遗留、修正的文档、提交（哈希与一句说明）。
- **保留**：保留的本会话文件及一句理由。
- **需要你决定**：待确认文件、未提交改动、未完成事项，给出建议做法。
- **验证**：复查和验证实际运行了什么、结果如何。

整体篇幅与会话规模相称；没有发现任何本会话产物时，直接说明并给出 `可以关闭`。
